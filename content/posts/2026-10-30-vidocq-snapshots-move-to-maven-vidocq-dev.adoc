image::/images/vidocq-banner.png[Vidocq banner,role=blog-banner]

Since July, every merge to `main` has published the Vidocq SNAPSHOTs to the Central Portal snapshot repository, as
link:/posts/using-the-vidocq-snapshot-builds/[we described then]. As of today they go to our own repository:

[source]
----
https://maven.vidocq.dev/snapshots/
----

Releases do not move: 0.4.0 and every release after it are published to Maven Central, as before.

== Why

On October 30, Central started refusing the token our CI publishes with. The SNAPSHOTs of `main` stopped reaching
the Central snapshot repository. Worse, the CI read the SNAPSHOTs it depends on with that same token, so every build
of `main` failed, even for artifacts anyone can download anonymously.

A new token would fix the symptom. But the SNAPSHOTs are the part of our publishing we use every hour, between
repositories that depend on each other, and we want that loop in our own hands. So we put it on a Reposilite we
run ourselves.

== What you get

* **Read access without an account.** `https://maven.vidocq.dev/snapshots/` is a plain Maven repository: browse
  it, point Maven or Gradle at it, `curl` it.
* **A mirror on a second site.** `https://maven.bak.vidocq.dev/snapshots/` serves the same SNAPSHOTs from another
  location, if the first one is down.
* **A short, predictable history.** The repository keeps the **five latest builds** of each SNAPSHOT version, so you
  can step back a few builds when one breaks you. A SNAPSHOT version no build has touched for 30 days is removed;
  old lines such as `0.3.0-SNAPSHOT` do not linger.
* **Only the CI publishes.** The CI is the only one that can write there, and only to the SNAPSHOT repository.

== The one line to change

A project that already builds against a Vidocq SNAPSHOT declares Central's snapshot repository. Replace its URL, in
both blocks: the Vidocq Maven plugin is a build extension, and Maven resolves build extensions from the plugin
repositories only.

[source,xml]
----
<repositories>
    <repository>
        <id>vidocq-snapshots</id>
        <url>https://maven.vidocq.dev/snapshots/</url>
        <releases><enabled>false</enabled></releases>
        <snapshots><enabled>true</enabled></snapshots>
    </repository>
</repositories>
<pluginRepositories>
    <pluginRepository>
        <id>vidocq-snapshots</id>
        <url>https://maven.vidocq.dev/snapshots/</url>
        <releases><enabled>false</enabled></releases>
        <snapshots><enabled>true</enabled></snapshots>
    </pluginRepository>
</pluginRepositories>
----

Then `mvn -U package` picks up the newest build. A project created with `vidocq create --parent-version
0.4.0-SNAPSHOT` from now on gets these blocks already, and the SNAPSHOT CLI installer and `vidocq update` read
the same repository.

The SNAPSHOTs already on Central's snapshot repository stay there until Central expires them, but no new Vidocq
SNAPSHOT will be published there.
