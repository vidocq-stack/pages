the official Eclipse Foundation TCK (EFTL) binaries.

=== Core Profile composite TCK

10/13 passed. The 3 not passing are unreachable on any JDK 25 implementation
regardless of conformance — a Jakarta TCK-helper incompatibility with the
documented `StackWalker` contract (`Utils.getDescriptor()` called without
`Option.RETAIN_CLASS_REFERENCE`), **not a Vidocq defect**. The challenge was
filed and is **accepted** by the TCK project:
https://github.com/jakartaee/platform-tck/issues/2730[`jakartaee/platform-tck#2730`].
The fix already exists upstream (merged January 2025) but has not yet shipped
in an official Core Profile TCK release.

=== Signature tests

All five constituent signature-test requirements are satisfied: Annotations,
JSON-P, JSON-B, RESTful WS, and CDI 4.1 Lite (`cdi-sigtest`, 0 failures against
`cdi-api-jdk17.sig`). There is no profile-level signature test — the Core
Profile TCK defers to each constituent specification's own signature test.

=== Verification method

All 7 EFTL binaries downloaded fresh from `download.eclipse.org` and verified
before the certifying run:

* **SHA-256**: 7/7 match.
* **GPG signature**: 7/7 valid — 2 signed by the current Jakarta EE
  Specification Committee key (`4C0C9898D7A2A593`: Core Profile 11, RESTful WS
  4.0.1), 5 by the previous committee key (`ABE05725E77C2B44`, since expired —
  expected for their earlier release dates: Annotations, CDI, Dependency
  Injection, JSON-P, JSON-B).

Full process, TCK binary references and detailed results:
https://codefloe.com/Vidocq/vidocq/src/branch/main/CERTIFICATION.md[`CERTIFICATION.md`]
in the `vidocq` repository.
